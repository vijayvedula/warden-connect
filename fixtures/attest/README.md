# Attestation fixtures

Generated by [`scripts/gen-attest-fixtures.py`](../../scripts/gen-attest-fixtures.py)
and read by `crates/wc-e2e/tests/attest.rs`, which drives `admission::admit` through
the **real** verifiers — `JwtSvidIdentity`, `JwksCardVerifier`,
`DsseProvenanceVerifier` — to `Posture::Attested`.

| File | Stage | What it is |
|---|---|---|
| `jwt-svid.token` | 1 · identity | A SPIFFE JWT-SVID: `sub` is the SPIFFE ID, `aud` the control plane, `exp` an hour after the fixture instant |
| `agent-card.signed.json` | 3 · card | An A2A card with a `signatures` array, signed over the canonicalised card with its own signature field removed |
| `provenance.dsse.json` | 4 · provenance | An in-toto Statement with a SLSA v1 predicate, inside a DSSE envelope |
| `artifact.bin`, `artifact.digest` | 4 | The subject the statement is bound to |
| `*.priv.pem`, `*.pub.pem` | — | Three keypairs: SPIFFE bundle, card signer, builder |
| `manifest.json` | — | The ids, audience, builder and digest the test reads rather than hard-codes |

## Why the material is not minted by our own Rust

A fixture produced by the code that reads it proves the code agrees with itself.
`wc-core::contract` already has round-trip tests for that. What they cannot tell you is
whether a **real** SPIRE token or a **real** SLSA envelope would be accepted, because
those come from other implementations.

So this is minted with `cryptography`, assembling the ES256 signatures as raw `R‖S` and
the DSSE pre-authentication encoding from the spec text. Agreement between the script
and the verifiers is two independent readings of SPIFFE, JOSE and DSSE — the closest
thing to an interop test that fits in a repository with no network.

## Three keys, on purpose

The SPIFFE trust bundle, the card signer and the builder are three roles held by three
parties. One key doing all three would let the test pass while the code confused them,
so `the_three_roles_are_three_keys_and_cannot_be_confused` puts the bundle key in the
card verifier's slot and asserts the card is refused.

## The private keys are checked in, deliberately

Same as [`fixtures/keys/`](../keys/README.md): these exist to make a test reproducible
and they sign nothing outside it. Regenerating is `rm -rf fixtures/attest && python3
scripts/gen-attest-fixtures.py`; the script reuses existing keys so a routine
regeneration does not invalidate a trust bundle somebody has configured against them.

## What this still does not prove — P0 #3's remaining half

The material is the right *shape* and it did not come out of a SPIRE server or a build
pipeline. That is why these are files rather than constants: point the test at real
output and re-run it.

```sh
# stage 1, against a running SPIRE agent
spire-agent api fetch jwt -audience warden-connect://control-plane/apac \
  | sed -n 's/^ *token: *//p' > fixtures/attest/jwt-svid.token
# and the bundle it should verify against. What SPIRE hands back is a JWKS, which
# `IssuerKeys::add_jwks` now reads directly — the conversion step this line used to
# ask for is gone.
spire-agent api fetch jwtbundles > fixtures/attest/spiffe-bundle.jwks.json

cargo test -p wc-e2e --test attest
```

The audience, the SPIFFE ID in `manifest.json` and the trust-bundle `kid` all have to
match what SPIRE actually issues, and the test will say which one does not.
